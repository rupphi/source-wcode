## Data ownership and recovery evidence

- JavaFX và jDesk dùng cùng lock trước `Database.initDatabase()`; contention/release tests pass.
- Snapshot dùng SQLite online backup, gồm committed WAL state, rồi integrity + SHA-256 verify.

  cover crash sau journal, WAL removal, SHM removal, DB replacement và marker publication; cleanup
  failure; snapshot mutation; directory/file symlink; corrupt DB; và trường hợp main DB giống hệt
  restore target nhưng WAL có committed row mới hơn.
- Fresh-context adversarial review sau hai remediation vòng: **APPROVED**, không còn blocker.

Development/canary recovery commands:

```bash
./gradlew wcodeRecovery --args='list'
./gradlew wcodeRecovery --args='verify <snapshot-id>'
./gradlew wcodeRecovery --args='restore <snapshot-id> --confirm'
```

CLI không khởi tạo normal database composition root, yêu cầu exclusive app-data lock, không in
absolute path/exception/secret. jDesk 0.1.3 Gradle plugin chưa expose secondary packaged launcher;
do đó launcher recovery trong installed app image vẫn là release-hardening item, chưa được tính
hoàn thành.
